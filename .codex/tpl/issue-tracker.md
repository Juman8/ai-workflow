## 種別の定義

| 種別 | 説明 | 例 |
|------|------|-----|
| 課題 | 対応が必要な問題・障害 | 仕様の矛盾、技術的な問題、スケジュール遅延 |
| 懸念 | まだ問題にはなっていないが注意が必要な事項 | リスク要素、検討中の方針 |
| 決定 | 検討の結果、合意・決定した事項 | 技術選定の決定、仕様の確定 |
| 質問 | 顧客・関係者への確認事項 | 要件の曖昧な箇所、仕様の確認 |
| 変更 | スコープ・仕様の変更要求 | 追加機能の要望、仕様変更 |

## ステータスの定義

| ステータス | 説明 |
|-----------|------|
| 未対応 | まだ対応に着手していない |
| 検討中 | 対応方針を検討中 |
| 対応中 | 担当者が対応中 |
| 確認待ち | 顧客・関係者への確認待ち |
| 完了 | 対応完了・解決済み |
| 保留 | 対応を一時保留（理由を備考欄に記載） |
| 対応不要 | 対応しないことを決定 |

---

## 優先度の定義（必要な場合）

| 優先度 | 説明 |
|--------|------|
| 高 | プロジェクトの進行・リリースに影響する重要課題 |
| 中 | 対応が望ましいが即時影響はない課題 |
| 低 | 余裕があれば対応する課題 |
